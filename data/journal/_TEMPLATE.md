# 日志填写指引（非骨架）

> 实际的空日志由 `node cli.js journal init` 生成，骨架在 `core/journal.js` 里维护，**不要复制本文去建文件**。
> 本文只说明每个区块写成什么样算合格。

---

## META —— 账户快照

由 `node cli.js journal sync` 生成，不要手填：

```markdown
| 项目 | 值 |
|---|---|
| 交易日 | 2026-11-09 周一 |
| 本金 | ¥50,000.00 |
| 现金 | ¥31,520.00 |
| 持仓 | 1 只 |
| 时段 | 连续竞价 |
| 累计盈亏 | +0.42% |
| 最后更新 | 14:45 |
```

数据取自服务实时账户，收盘后再 sync 一次即得当日终值。

## 时间线 —— 一条一个事实

合格：

```markdown
- `09:05` **[计划]** 今日计划已定：持仓 0，只做 512890 一档，上限 1.2 万，不追高
- `09:45` **[交易]** 买入 512890 红利低波ETF 12000 份 @1.237，金额 14,844，计划第 1 批
- `10:12` **[风控]** 盘口价差扩大至 0.8%，暂停追加买入（流动性异常）
- `14:45` **[风控]** 无止损触发；隔夜仓位 30%，现金 70%，明日不追高
```

不合格（缺主体、缺数字、无法复核）：

```markdown
- `09:45` **[交易]** 今天买了点红利，还行
- `14:45` **[记录]** 一切正常
```

多行条目用缩进续行（命令行会自动处理）：

```markdown
- `15:15` **[复盘]** 今日未交易，原因有三
  一、情景一触发（创业板 -2.3%），按计划只做 8,500 份
  二、512890 盘中最低 1.228 跌破 MA20 1.232，触发 C 级证伪
  三、结论：不买是对的
```

## 今日计划 —— 必须能直接执行

三条必写，缺一条就不算合格计划：

1. **持仓处置**：每只票的止损价、止盈价、是否减仓（空仓则写"无持仓"）
2. **候选与触发条件**：买什么、什么价位/信号才买、买多少股
3. **今日笔数上限**：最多几笔，超了就停

示例（节选）：

```markdown
> 情景闸门：创业板跌幅 >2% 只做最小档；跌幅 <1% 按表执行

| 批次 | 标的 | 数量 | 金额 | 触发条件 |
|---|---|---|---|---|
| 第 1 批 | 512890 | 12,000 份 | 1.48 万 | 守住 MA20 1.232 |
| 情景一改 | 512890 | 8,500 份 | 1.05 万 | 跌破 MA20 但未破 1.190 |

- 今日最多 2 笔（含卖出）
- 止损：无持仓，不适用
```

**禁止**写"择机买入""视情况而定"——那等于没计划。

## 收盘复盘 —— 五项齐全

1. 今日成交明细与费用（含最低佣金 5 元的影响）
2. 当日盈亏与累计盈亏（相对本金）
3. 每笔交易归因：**判断错**还是**执行错**，二者分开
4. 是否违反风控纪律（追高、超仓、频繁交易、未执行止损）
5. 明日计划初稿（持仓处置 + 1~3 只关注标的 + 触发条件）

没有成交时，第 1、3 项写"无交易"，但第 5 项不能空——空仓也是一种仓位安排。
