# 日志规范

本目录是**业务日志**（每个交易日一篇），记录决策、成交、风控与复盘。
工程侧的改动（改代码、改规则、改配置）记在仓库根目录的 [`CHANGELOG.md`](../../CHANGELOG.md)，两者不混写。

---

## 1. 一条铁律：只通过命令行写

```bash
node cli.js note  ...        # 时间线
node cli.js journal plan     # 今日计划
node cli.js journal review   # 收盘复盘
```

**不要用编辑器或 `echo >>` 直接改这些文件。** 文件里用 HTML 注释做区块锚点，手写极容易写坏锚点、把条目塞到错误区块，后续解析就废了。命令行写入会自己处理锚点、排序、账户快照和索引。

## 2. 文件与命名

| 项 | 约定 |
|---|---|
| 位置 | `data/journal/YYYY-MM-DD.md`，一个交易日一篇 |
| 命名 | 日期即交易日。**周末与节假日不建新文件**（除非有手工操作需要留痕） |
| 索引 | `INDEX.md`，由 `node cli.js journal index` 生成，**不要手改** |
| 归档 | 超过 90 天移入 `archive/`：`node cli.js journal archive --days 90` |
| 预留名 | `README.md`、`_TEMPLATE.md`、`INDEX.md` 不参与索引 |

## 3. 文件结构（四个区块）

```markdown
# 2026-11-09 周一 · 盯盘日志

<!-- META:START -->   ← 账户快照（journal sync 生成）
<!-- META:END -->

## 时间线
<!-- TL:START -->      ← 只增不改，按 HH:MM 正序插入
<!-- TL:END -->

## 今日计划
<!-- PLAN:START -->    ← 覆盖写入，一天可以有多次修正
<!-- PLAN:END -->

## 收盘复盘
<!-- REVIEW:START -->  ← 覆盖写入，收盘后一次
<!-- REVIEW:END -->
```

必要时文件末尾会有 `## 历史正文（迁移自旧格式）`，那是自动迁移时保留的原文，**只读**。

### 区块职责

| 区块 | 写什么 | 谁写 | 覆盖还是追加 |
|---|---|---|---|
| META | 本金、现金、持仓数、时段、累计盈亏、最后更新 | `journal sync` | 覆盖 |
| 时间线 | 发生了什么、做了什么、看到了什么信号 | `note` | 追加（按时间插入） |
| 今日计划 | 今天打算怎么做、触发条件、仓位上限 | `journal plan` | 覆盖 |
| 收盘复盘 | 计划 vs 实际、归因、明日预案 | `journal review` | 覆盖 |

**为什么时间线不能随手追加**：旧实现是往文件末尾追加，结果盘前写下的长计划把时间线挤散，15:49 的条目排到了"证伪信号"后面。现在按 `HH:MM` 插入，乱序执行也能保持正序。

## 4. 标签

时间线条目必须带标签，取值固定为：

| 标签 | 用途 |
|---|---|
| `计划` | 计划相关动作（生成、修正、放弃） |
| `交易` | 下单、成交、撤单 |
| `风控` | 止损/止盈触发、超限告警、探活失败 |
| `复盘` | 盘后归因 |
| `运维` | 服务启停、配置变更、日志体系本身 |
| `自检` | 连通性/链路验证 |
| `记录` | 兜底，未归类的事实 |

```bash
node cli.js note --tag 交易 "09:45 买入 512890 12000 份 @1.237，计划第 1 批"
node cli.js note --tag 风控 "10:12 600900 触及 -7% 止损线，市价卖出 400 股"
```

**时间戳**：默认取当前时刻；补写历史条目时用 `--at 09:45`，或让内容以 `09:45 ` 开头（会自动提取为时间并从正文去掉）。

## 5. 什么时候写什么

| 时点 | 动作 | 命令 |
|---|---|---|
| 09:05 盘前 | 写今日计划（持仓处置 + 候选与触发条件 + 笔数上限） | `journal plan` |
| 09:45 / 14:45 | 每笔成交、每次风控触发 | `note --tag 交易/风控` |
| 盘中修正 | 计划变了就重写计划区，别在时间线里覆盖 | `journal plan` |
| 尾盘补充 | 隔夜仓位与明日预案接到原计划后面 | `journal plan --append` |
| 15:15 收盘 | 计划 vs 实际、归因、明日预案 | `journal review` |
| 任意 | 刷新账户快照 | `journal sync` |

> `journal plan` 默认**覆盖**计划区；`--append` 才追加（尾盘补充明日预案时必须带，否则会冲掉早盘计划）。

`note` 与 `journal` 是纯文件操作，**服务没起来也能写**，故障现场必须靠它留证。

## 6. 写作要求

- **带数字**：写"512890 12,000 份 @1.237，约 1.48 万，占仓 30%"，不写"买入红利 ETF"。
- **可核查**：写"止损 1.150（成本 -7%）"，不写"注意风险"。
- **区分两类错**：判断错（方向看错）与执行错（没按计划做）必须分开写，否则复盘没有改进点。
- **没交易也要写原因**：空仓等待是决策，不是空白。
- 一条记录一件事。多件事拆多条，别写成一篇散文。

## 7. 新会话怎么用

```bash
node cli.js journal brief --days 3   # 最近三天计划与复盘摘要
node cli.js journal show 2026-11-09  # 某日全文
node cli.js journal index            # 重建索引
```

完整约定见仓库根目录 [`AGENTS.md`](../../AGENTS.md)。
