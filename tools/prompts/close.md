# 收盘复盘（15:15，不交易）

工作目录 `D:/workTest/trade-desk`，服务 `127.0.0.1:5193`。

## 第 0 步
1. `node cli.js status` → 休市：一行说明，不写日志，结束。
2. `node cli.js alert poll` → 收盘后仍 `PENDING` 的逐条定性（真突破/噪声/漏判），`alert ack <id> --note "收盘后定性"`。

## 第 1 步 · 对照链
`node cli.js journal show` 读全文：今日计划（含 `--append` 变更）+ 时间线里的执行与区间记录。
逐条对照：计划了什么、实际做了什么、偏离在哪、为什么。计划区被覆盖过就到 `data/journal/plan-archive/<日期>/` 翻旧版。

## 第 2 步 · 快照
`node cli.js journal sync`。

## 第 3 步 · 写复盘
`node cli.js journal review "..."`。必须含六项：
1. 成交明细与费用（注意最低佣金 5 元对小单的费率影响）；
2. 当日与累计盈亏（相对本金）；
3. 每笔归因：**判断错**还是**执行错**，必须分开写；
4. 是否违反风控纪律，逐条对 `AGENTS.md` §3；
5. 区间触发有效性：触发几次、有效还是噪声、区间要不要调；
6. 明日计划初稿：持仓处置 + 1~3 只标的 + 触发条件 + 四档闸门（含情景零）。写具体价位，不写「择机」。

注意：**不要用今天下午才新立的规矩去判今早的行为**。规则若当日才加进 `AGENTS.md`，定性应为「制度空白，今日已补」，不是「当日违规」——否则违规统计会被假账稀释。

## 第 4 步 · 观察池收尾
`node cli.js watch list` 看存活；逻辑已破的 `watch rm <代码> --reason "..."`；`watch prune` 收尾。复盘里补一句「今日 N 只、触发 M 只、退役 K 只」。

## 第 5 步
`node cli.js journal index`。不交易、不撤单。若当日 0 成交，必须写明原因：闸门不成立，还是执行犹豫。

全程中文，金额用 ¥，红涨绿跌。
