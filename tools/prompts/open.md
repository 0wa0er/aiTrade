# 开盘执行（09:45，当天主要买入窗口）

工作目录 `D:/workTest/trade-desk`，服务 `127.0.0.1:5193`。

## 第 0 步
1. `node cli.js status` → 休市/不可委托：终端一行说明，**不写日志**，结束。
2. `node cli.js alert poll --check` → `PENDING` 逐条处理：`quote` 核对 → 判突破还是噪声 → 处置 → `alert ack <id> --note "结论"`。
3. `node cli.js cond check` → 条件单到点/到价会在这里执行。逐条核对结果：`已执行` 记进时间线；`执行被拦` 要读懂原因（额度不足？超单票上限？无持仓？），再决定是改计划还是留到明天。随后 `node cli.js cond list` 看今日还有哪些单待触发。

## 第 1 步 · 读计划
`node cli.js journal show` 读「今日计划」。无计划则用 `journal brief --days 2` 取上一交易日。

## 第 2 步 · 先处理持仓
`node cli.js risk`：
- 止损：跌破成本 -7% → 无条件 `node cli.js sell` 全卖，不等尾盘。
- 止盈：**当日最高曾 ≥+15% 且现价自高点回落 ≥3%** → 卖一半。（不是「现价仍 +15%」，那会漏掉冲高回落。）
- 结构：跌破建仓日 BOLL 下轨 → 离场（比 -7% 早，谁先到按谁）。
- 止损优先于任何买入。

## 第 3 步 · 用本次运行时刻的数据重判闸门
禁止沿用计划里更早时点的判断、禁止沿用昨日数字。涨跌家数、涨停家数从实时接口取。
- 情景零 强势放量（上涨占比 >65% 且 成交额较上日放大）→ 买满一档，**只买回踩位**，不追当日涨幅 >5%；
- 情景一 继续杀跌（创业板跌 >2% 或 上证破 3600）→ 只买最小一档；
- 情景二 低开震荡（跌幅 <1%）→ 按计划买满一档；
- 情景三 反弹修复（科创50 站回 MA20 且 涨停 >45）→ 只建一档；
- 均不成立 → 不下单，写清哪条不成立。

## 第 4 步 · 下单
- 先 `node cli.js buy <代码> <股数> --dry-run`，通过再去掉 `--dry-run`。
- 额度以 `node cli.js risk` 的 `maxSingleValue / maxDailyBuy` 为准，不要写死 1.5 万。
- 一天只建一档，买满即停，不拆单、不追加。

## 第 5 步 · 留痕
- 每笔成交 `node cli.js note --tag 交易 "标的/方向/数量/成交价/依据/第几批"`。
- 不下单也要记 `note --tag 记录 "各情景实测值 + 为何不成立"`。

## 第 6 步 · 改计划
盘中实质修改**必须** `node cli.js journal plan --append`，禁止覆盖——覆盖会毁掉复盘的对照链。
